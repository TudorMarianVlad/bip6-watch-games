# Wristlings creature art — current status (2026-11-23)

## Where it stands

- **106 / 106 species have their own art.** No borrowed sprites, no "?" eggs, no "needs art" tags.
  `docs/roster.html` is the visual source of truth; it is regenerated by `node tools/roster.cjs`.
- The app icon is the round Gemini Sprig icon from `tools/icon_gemini.png`; regenerate it with
  `node tools/icon.cjs --look`.
- Per-creature art descriptions, stats, rarity, evolution, berries and moves are in
  [creatures.md](creatures.md).
- Every source image is `Wristlings/art/<id>.png` (RGBA PNG, transparent canvas). The 65 Gemini
  `.jfif` images that still had a white canvas were converted and stripped of their **outer**
  edge-connected white; enclosed white markings were left alone unless explicitly selected.
- The importer generates `assets/default.{s,r,b}/mon/<id>.png` at 128, 112, 64 px plus the book
  silhouette. It removes only background reachable from the image edge, so white pockets inside a
  creature stay white. All 424 generated sprites have transparent corners.
- The user reviewed the whole roster on 2026-11-23 and approved the art.

- Review pages that used numbered boxes to pick white pockets were scratch artifacts and have been
  deleted. Nothing in the game depends on them.

## Workflow after an Aseprite edit

From a normal Command Prompt (PowerShell needs `.\reimport.cmd`):

```
cd /d "C:\Users\xxkor\Bip6 Games\Wristlings\tools"
reimport.cmd <id1>,<id2>
```

Save over the same `art/<id>.png` first. The helper runs the importer, named sheet, widget preview,
roster, browser preview, published demos and `zeus build`. For a whole-folder re-import, run the same
steps with `node tools/import.cjs` instead of `import.cjs --only <ids>`.

Use `docs/roster.html` to judge the art. `tools/sheet_named.png` is only a labelled review grid on a
dark background, so deliberately transparent areas appear as dark holes there; that is expected.
